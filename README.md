# AI Workout Plan Generator

A single-page Streamlit app that turns a few structured answers about your fitness goals
into a personalised, day-by-day weekly workout plan, generated by an LLM through the
[Groq API](https://console.groq.com/).

## Features

- **Structured inputs**, not one text box: fitness goal, experience level, days per week,
  time per day, equipment access (multi-select) and optional injuries or limitations.
- **A usable 7-day plan**: workout, rest and active-recovery days, each workout split into
  warm-up, main and cool-down, with sets, reps, rest times and form notes.
- **Constraints respected**: only the equipment you have, exactly the number of workout days
  you chose, sessions sized to your available time, exercises adapted to injuries.
- **Safety**: risky exercises are swapped for safer ones, every adaptation is listed as a
  safety note, and a disclaimer is shown when a real physical limitation is entered.
- **Regenerate** for a new variation, **Download** the full plan as a Markdown file.
- **Friendly error messages, never a crash**: invalid inputs, bad API key, network problems,
  rate limits, cut-off, empty or malformed replies.
- **Debug view**: expanders show the exact JSON sent to the LLM and the raw reply.

## Tech stack

Python 3.13 · Streamlit · Groq (`openai/gpt-oss-20b`) · python-dotenv · [uv](https://docs.astral.sh/uv/)

## Setup

1. Install [uv](https://docs.astral.sh/uv/getting-started/installation/).
2. Clone the repo and install dependencies:
   ```bash
   git clone https://github.com/sakthivelsathyanarayanan/ai-workout-plan-generator.git
   cd ai-workout-plan-generator
   uv sync
   ```
3. Create a free API key at [console.groq.com/keys](https://console.groq.com/keys), then
   copy `.env.sample` to `.env` and add it:
   ```
   GROQ_API_KEY=your_key_here
   GROQ_MODEL=openai/gpt-oss-20b
   ```

## Run

```bash
uv run streamlit run app.py
```

The app opens at http://localhost:8501. Fill in the form and click **Generate plan**.

## How it works

1. The form answers are validated and turned into a structured JSON input
   (`llm_input.py`).
2. `generate_workout_plan()` (`llm_client.py`) sends a system prompt plus that JSON to Groq
   with **strict structured output**, so the reply must match the plan schema.
3. The reply is checked against the schema again (`llm_output.py`) and rendered as a summary
   card, safety notes and one tab per day. Anything that doesn't match is shown as raw text
   instead of crashing.

Diagrams of the components, request flow, error handling and data contract are in
[ARCHITECTURE.md](ARCHITECTURE.md).

## Prompt design

The system prompt was improved step by step; all versions are kept in `SYSTEM_PROMPTS` in
[llm_client.py](src/ai_workout_plan_generator/llm_client.py) so outputs can be compared
(`ACTIVE_PROMPT` selects one).

| Version | What it adds | What changed in the output |
|---|---|---|
| v1 | One-line baseline | Markdown with emoji and tables, own structure, rest days barely mentioned |
| v2 | Trainer role, meaning of every input field | Used rest days and session length on purpose; still free text |
| v3 | Plan rules (7 days, workout count, time, equipment, phases), experience-level guidance, JSON output with the schema | First JSON plans the UI could render; one run still dropped `days` |
| v4 (active) | Equipment definitions, session length, injury safety, disclaimer flag, treating user text as data | Risky exercises swapped instead of just warned about; a "write a poem" injection ignored; disclaimer only for real limitations. A worked example was tried and removed because the model copied its exercises |

Alongside the prompt: strict `response_format`, `temperature` 0.3 for steadier JSON, a
token limit of 8192 and up to 3 automatic retries when Groq rejects a reply as invalid JSON.

## Error handling

Every failure inside `generate_workout_plan()` becomes an `LLMError` whose message is shown
under the form:

- **Invalid inputs**: no equipment selected, days outside 1–7, no time.
- **API failures**: missing or invalid key, no access to the model, wrong model name, rate
  limit, token limit (413), server errors, timeouts, no connection.
- **Bad replies**: cut off at the token limit (with token usage), empty, or rejected as
  invalid JSON after 3 tries. A reply that doesn't match the schema falls back to raw text.

## Notes

- Groq's free tier has per-minute and per-day token limits. If you see "rate limit" or
  "token limit" messages, wait a minute and try again.
- Plans are general fitness guidance, not medical advice.
